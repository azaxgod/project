# Анализ реализации тикетов по EPIC 5

## ✅ Что уже реализовано

1. **Базовая структура:**
   - Модель `Ticket` с основными полями
   - Модель `TicketAssignment` 
   - `TicketsController` и `TicketsState`
   - Базовая страница `TicketsPage` с таблицей
   - Диалог создания тикета для KGU ZKH

2. **Фильтры:**
   - Статус тикета
   - Подрядчик (для KGU ZKH и Акимата)
   - Участок
   - Контракт
   - Плановый период (в state, но не в UI)
   - Фактический период (в state, но не в UI)

3. **Таблица:**
   - ID тикета
   - Участок
   - Подрядчик
   - Контракт
   - Период
   - Статус
   - Кол-во рейсов
   - Объём вывезен (м³)
   - Нарушения (иконка)
   - Действия (для KGU ZKH и Подрядчика)

4. **Базовые действия:**
   - Создание тикета (KGU ZKH)
   - Отмена тикета (KGU ZKH, только PLANNED)
   - Закрытие тикета (KGU ZKH, только COMPLETED)

## ❌ Что отсутствует или требует исправления

### 1. КРИТИЧНО: Нет загрузки тикетов с бэкенда
- **Проблема:** `TicketsController._loadData()` возвращает пустой список тикетов (`final tickets = <Ticket>[];`)
- **Требуется:** Создать `TicketsRepository` и интегрировать с Operations Service

### 2. Нет управления ticket_assignment
- **Проблема:** Нет UI для назначения водителей/техники на тикет
- **Требуется:** 
  - Добавить колонку "Назначено водителей" в таблицу
  - Создать диалог назначения водителей/техники (для Подрядчика)
  - Реализовать методы создания/удаления назначений

### 3. Нет детальной страницы тикета
- **Проблема:** Кнопка "Подробнее" только вызывает `controller.selectTicket()`, но нет страницы детального просмотра
- **Требуется:** 
  - Создать `TicketDetailPage` с:
    - Информацией о тикете (участок, подрядчик, контракт, периоды)
    - Списком назначений (ticket_assignment)
    - Списком рейсов (trip) с фото LPR/Volume
    - Списком нарушений
    - Списком обжалований (appeal)

### 4. Нет UI для водителя
- **Проблема:** Нет мобильной версии и кнопок "В работе"/"Завершено"
- **Требуется:**
  - Создать мобильную версию страницы тикетов для водителя
  - Добавить кнопки "В работе" и "Завершено"
  - Реализовать логику перехода статуса тикета в IN_PROGRESS/COMPLETED

### 5. Проблемы с правами доступа
- **Проблема:** 
  - Акимат должен видеть все тикеты (сейчас фильтруется только подрядчик)
  - Подрядчик должен видеть только свои тикеты (реализовано)
  - Водитель должен видеть только свои тикеты (не реализовано)
- **Требуется:** Исправить фильтрацию по ролям

### 6. Нет фильтров по периодам в UI
- **Проблема:** `periodStart`, `periodEnd`, `factPeriodStart`, `factPeriodEnd` есть в state, но нет в UI
- **Требуется:** Добавить DateRangePicker для планового и фактического периодов

### 7. Нет логики проверки для COMPLETED
- **Проблема:** `closeTicket()` не проверяет условия из EPIC:
  - Все рейсы закрыты (polygon_exit_time заполнено)
  - Объём на выезде ≈ 0 для рейсов с exit_volume_event
- **Требуется:** Реализовать проверки перед переводом в COMPLETED

### 8. Нет колонки "Назначено водителей"
- **Проблема:** В таблице нет информации о количестве назначений
- **Требуется:** Добавить колонку с COUNT(ticket_assignment) для Подрядчика

### 9. Нет редактирования тикета
- **Проблема:** KGU ZKH не может редактировать тикет до начала фактов
- **Требуется:** Добавить кнопку "Редактировать" и диалог редактирования

### 10. Нет перевода тикета в IN_PROGRESS/COMPLETED для Подрядчика
- **Проблема:** Подрядчик не может переводить тикет в IN_PROGRESS/COMPLETED
- **Требуется:** Добавить кнопки и логику для Подрядчика
