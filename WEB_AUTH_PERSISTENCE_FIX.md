# Исправление сохранения авторизации на вебе

## ✅ Проблема:
При обновлении страницы (F5) на веб-версии пользователь выходил из аккаунта и нужно было заново регистрироваться.

## ✅ Решение:

### 1. Добавлен слушатель `authStateChanges()`
- `AuthNotifier` теперь подписывается на изменения состояния Firebase Auth
- Автоматически обновляет состояние при изменении авторизации
- Работает как на вебе, так и на мобилке

### 2. Улучшено восстановление состояния при старте
- Добавлена задержка для восстановления состояния Firebase Auth (особенно важно на вебе)
- Двойная проверка: сначала через `currentUser`, затем повторная проверка через 300ms
- Это решает проблему, когда Firebase Auth еще не успел восстановить состояние из localStorage

### 3. Роутер ждет восстановления состояния
- `appRouterProvider` теперь ждет, пока `isCheckingToken` станет `false`
- Максимальное время ожидания: 2 секунды (20 попыток по 100ms)
- Это гарантирует, что роутер использует актуальное состояние авторизации

### 4. Правильная очистка ресурсов
- Добавлен метод `dispose()` для отмены подписки
- Провайдер автоматически очищает подписку при удалении

## 📁 Измененные файлы:

- `lib/modules/auth/src/controller/auth_notifier.dart`:
  - Добавлен `StreamSubscription` для `authStateChanges()`
  - Улучшена логика восстановления состояния
  - Добавлен метод `dispose()`

- `lib/core/routes/app_routes.dart`:
  - Добавлено ожидание восстановления состояния Firebase Auth
  - Роутер теперь использует актуальное состояние авторизации

## 🔧 Как это работает:

1. **При старте приложения:**
   - `AuthNotifier` проверяет `FirebaseAuth.instance.currentUser`
   - Если пользователь найден → создается `User` и обновляется состояние
   - Если не найден → ждет 300ms и проверяет снова (для веба)
   - Подписывается на `authStateChanges()` для отслеживания изменений

2. **При обновлении страницы (F5):**
   - Firebase Auth автоматически восстанавливает состояние из localStorage (на вебе)
   - `authStateChanges()` срабатывает и обновляет состояние в `AuthNotifier`
   - Роутер ждет восстановления состояния перед определением `initialLocation`
   - Восстанавливается сохраненный роут из `RouteStorage`

3. **При навигации:**
   - Роут сохраняется в `RouteStorage` через listener
   - При следующем обновлении страницы роут восстанавливается

## ✅ Результат:

- ✅ При обновлении страницы (F5) пользователь остается авторизованным
- ✅ Пользователь остается на той же странице, где был
- ✅ Работает на вебе и мобилке
- ✅ Firebase Auth правильно восстанавливает состояние из localStorage (веб) / SharedPreferences (мобилка)
